Compara familias de bases de datos y aprende a pensar un endpoint desde el contrato antes de escribirlo en un lenguaje específico.

Bases de datos relacionales

Organizan información en tablas relacionadas mediante claves. Son útiles cuando importan las relaciones, las reglas de integridad y las transacciones consistentes.

Relacional

PostgreSQL

Adecuada para sistemas con consultas complejas, integridad fuerte y características avanzadas. Ejemplo: pedidos, inventario y reportes.

Relacional

MySQL

Muy utilizada en aplicaciones web, tiendas y sistemas de contenido que necesitan tablas y consultas SQL.

Relacional

SQL Server

Frecuente en empresas y entornos Microsoft para facturación, finanzas, reportes y sistemas administrativos.

Bases de datos no relacionales o NoSQL

No obligan a representar todo mediante tablas relacionadas. Existen varios modelos: documentos, clave-valor, columnas amplias y grafos.

Documentos

MongoDB

Guarda documentos parecidos a JSON. Resulta útil para catálogos con atributos variables, contenido y prototipos que evolucionan rápido.

Clave-valor

Redis

Busca valores muy rápido usando una clave. Es común para caché, sesiones, contadores y carritos temporales.

Columnas amplias

Cassandra

Se usa en grandes volúmenes distribuidos que requieren alta disponibilidad, como eventos, telemetría o actividad masiva.

Clave-valor y llave-valor significan lo mismo. Una clave única permite recuperar un valor. Ejemplo: cart:user-42 → { products: [5, 8] }. Es parecido a buscar un casillero por su número.

Sección independiente: todo lo básico de un endpoint

Un endpoint es una operación concreta que una API expone. No es únicamente la URL: también incluye el método HTTP, las entradas esperadas, validaciones y posibles respuestas.

Método HTTPGET consulta, POST crea o ejecuta una acción, PUT actualiza y DELETE elimina.
Ruta/api/products identifica el recurso o acción disponible.
Path parameter/api/products/5 identifica un recurso concreto.
Query parameter?active=true filtra, ordena o pagina.
HeadersMetadatos como Content-Type y Authorization.
BodyDatos enviados normalmente en POST, PUT o PATCH.
ValidacionesComprueban tipos, campos obligatorios y reglas del negocio.
RespuestaCódigo HTTP y cuerpo JSON que explican el resultado.

Ejemplo de POST en Node.js

Implementación mínima con Express

app.post('/api/accion', (req, res) => {
  const { edad } = req.body;

  if (typeof edad !== 'number') {
    return res.status(400).json({
      error: 'La edad es obligatoria y numérica'
    });
  }

  if (edad > 18) {
    return res.status(200).json({
      message: 'Acción permitida'
    });
  }

  return res.status(403).json({
    error: 'Debes ser mayor de 18 años'
  });
});

Pseudocontrato independiente del lenguaje

MÉTODO: POST
ENDPOINT: /api/accion

  EN CASO CONTRARIO

Seguridad y arquitectura del material de clase

API Gateway

Recibe el tráfico, enruta solicitudes, valida tokens, limita peticiones y protege servicios internos.

CORS, CSRF y CSP

CORS controla orígenes del navegador; CSRF evita acciones no autorizadas con una sesión; CSP restringe fuentes de scripts.

OAuth2 con PKCE

Permite autorización delegada sin compartir la contraseña con la aplicación cliente. PKCE protege el intercambio de código en apps públicas.
