Cómo diseñar un endpoint

Un ejemplo paso a paso para pasar de una idea escrita en lenguaje común a un contrato y finalmente a código Node.js.

Idea principal: primero define qué recibe y qué responde el endpoint. Después elige el lenguaje para implementarlo.

API y endpoint no son lo mismo

API

Es el conjunto completo de operaciones que un sistema ofrece. Puede contener autenticación, productos, clientes y pedidos.

Endpoint

Es una operación específica de la API, identificada principalmente por un método HTTP y una ruta.

Ejemplo sencillo

La API es el menú completo. POST /api/accion es una opción concreta que puede solicitarse.

Anatomía completa de un endpoint

ElementoPregunta que respondeEjemploPara qué sirve
Método HTTP¿Qué acción se realizará?POSTIndica que el cliente enviará información para crear o ejecutar una acción.
Ruta¿Dónde está disponible?/api/accionIdentifica la operación dentro de la API.
Headers¿Qué metadatos acompañan la solicitud?Content-Type: application/jsonDescribe el formato, autenticación u otras condiciones.
Body¿Qué información envía el cliente?{ "edad": 25 }Transporta los datos que el endpoint procesará.
Validación técnica¿El dato existe y tiene el tipo correcto?edad debe ser numéricaEvita procesar entradas incompletas o inválidas.
Regla del caso¿Cumple la condición del negocio?edad > 18Decide si la acción está permitida.
Código HTTP¿Cómo terminó la solicitud?200, 400 o 403Comunica el resultado de forma estándar.
Response body¿Qué detalle recibirá el cliente?{ "message": "Acción permitida" }Entrega datos o una explicación del resultado.

Contrato estructurado del ejemplo

Parte del contratoDefinición
NombreValidar acceso por edad
Método y endpointPOST /api/accion
PropósitoPermitir la acción únicamente cuando la edad sea mayor que 18.
Content-Typeapplication/json

Flujo paso a paso

#AcciónResultado
1Recibir POST /api/accion.El endpoint obtiene el body.
2Comprobar que edad exista y sea numérica.Si falla, responder 400.
3Evaluar edad > 18.Si se cumple, continuar al caso correcto.
4Responder el caso correcto.200 OK con mensaje de confirmación.
5Si no supera 18, negar la operación.403 Forbidden con explicación.

Implementación en Node.js con Express

Endpoint completo

app.post('/api/accion', (req, res) => {
  const { edad } = req.body;

  if (typeof edad !== 'number') {
    return res.status(400).json({
      error: 'La edad es obligatoria y numérica'
    });
  }

  if (edad > 18) {
    return res.status(200).json({
      message: 'Acción permitida'
    });
  }

  return res.status(403).json({
    error: 'Debes ser mayor de 18 años'
  });
});

Lista de revisión para cualquier endpoint

  • Definir claramente el método HTTP y la ruta.
  • Indicar parámetros, headers y body esperados.
  • Separar validaciones técnicas de reglas del negocio.
  • Documentar el caso correcto y los casos de error.
  • Usar códigos HTTP coherentes.
  • Mostrar ejemplos de solicitud y respuesta.
  • No exponer contraseñas, secretos o información innecesaria.
