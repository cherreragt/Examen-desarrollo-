Idea central: los microservicios no son automáticamente mejores. Permiten desplegar y escalar áreas por separado, pero agregan redes, latencia, monitoreo y consistencia distribuida.

Monolítico frente a microservicios

¿Qué es una aplicación monolítica?

Clientes, productos, facturación y otras áreas se ejecutan como una sola aplicación desplegable. Es sencilla para comenzar y permite transacciones directas, pero al crecer puede quedar muy acoplada.

¿Qué es un microservicio?

Es un servicio pequeño y autónomo que representa una capacidad del negocio, como carrito o pagos. Puede desplegarse y escalarse sin publicar toda la aplicación.

AspectoMonolitoMicroservicios

EscaladoSe escala toda la aplicación.Se escala solo el servicio con mayor demanda.

API frente a endpoint

¿Qué es una API?

Es el conjunto de reglas y operaciones que una aplicación ofrece para comunicarse con otras. Puede incluir productos, clientes, pedidos y autenticación.

¿Qué es un endpoint?

Es una dirección y operación específica dentro de la API. Ejemplo: GET /api/products/8.

Diferencia sencilla

La API es como el menú completo de un restaurante; un endpoint es una opción concreta del menú que puedes solicitar.

JWT: explicación técnica y sencilla

JWT significa JSON Web Token. Suele utilizarse para que una API pueda verificar identidad y permisos sin mantener una sesión tradicional en memoria para cada usuario.

1. Header / EncabezadoIndica el tipo de token y el algoritmo de firma, por ejemplo HS256.
2. Payload / ClaimsContiene afirmaciones como identificador, rol y vencimiento.
3. Signature / FirmaPermite detectar si alguien modificó el encabezado o los claims.

Analogía: el encabezado indica cómo está fabricado el gafete; los claims dicen de quién es y qué permiso tiene; la firma es el sello que permite comprobar que no fue alterado.

Aclaración técnica: un JWT común está codificado con Base64URL y firmado, no cifrado. Su payload puede leerse. En este ejemplo, HS256 es el algoritmo de firma; para ocultar contenido se necesitaría cifrado como JWE.

HEADER
{ "alg": "HS256", "typ": "JWT" }

PAYLOAD / CLAIMS
{ "sub": "42", "role": "Admin", "exp": 1790000000 }

TOKEN
base64Url(header).base64Url(payload).signature

Protocolos básicos

HTTP

Comunicación web sin cifrado propio. Comúnmente usa el puerto 80.

HTTPS

HTTP protegido con TLS para cifrar la comunicación. Comúnmente usa el puerto 443.

FTP

Protocolo tradicional para transferir archivos; por sí solo no protege credenciales y contenido.

SSH

Acceso remoto seguro a equipos y ejecución de comandos cifrados. Comúnmente usa el puerto 22.
