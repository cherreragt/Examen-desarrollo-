SOAP, REST, HTTP y formatos de datos

Antes del examen encontrarás definiciones y ejemplos pequeños. La meta es reconocer cuándo usar cada concepto, no memorizar palabras aisladas.

Orden de estudio: comienza con SOAP, REST y HTTP; compara JSON con XML; después revisa URI y migraciones.

¿Qué es una API REST?

Es una forma de exponer recursos mediante URLs y operaciones HTTP. Por ejemplo, GET /api/products/5 consulta el producto 5.

¿Qué es SOAP?

Es un protocolo de mensajería para servicios web. Usa mensajes XML con una estructura formal llamada Envelope.

¿Qué es HTTP?

Es el protocolo usado para enviar solicitudes y respuestas. Incluye métodos como GET y POST, además de códigos como 200, 201 y 404.

¿Qué es un schema en SOAP?

Un esquema XSD define la estructura y los tipos permitidos en los mensajes XML: campos, números, textos y elementos obligatorios.

SOAP frente a REST

AspectoSOAPREST
NaturalezaProtocolo con reglas formales.Estilo para diseñar servicios alrededor de recursos.
Formato comúnXML.Normalmente JSON, aunque puede usar otros formatos.
ContratoSuele describirse con WSDL y esquemas XSD.Usa endpoints y métodos HTTP; puede documentarse con OpenAPI.
Uso sencilloServicios con contratos XML estrictos.Aplicaciones web y móviles con APIs ligeras.

Ejemplo mínimo de un servicio REST y uno SOAP

REST: consultar producto 5

GET /api/products/5

Respuesta 200 OK
{
  "id": 5,
  "name": "Teclado",
  "price": 250
}

SOAP: consultar producto 5

POST /ProductService
Content-Type: text/xml

<soap:Envelope>
  <soap:Body>
    <GetProduct>
      <id>5</id>
    </GetProduct>
  </soap:Body>
</soap:Envelope>

La misma información en JSON y XML

JSON con 4 atributos

{
  "id": 5,
  "name": "Teclado",
  "price": 250,
  "available": true
}

XML con los mismos 4 atributos

<product>
  <id>5</id>
  <name>Teclado</name>
  <price>250</price>
  <available>true</available>
</product>

Diferencia principal: ambos representan datos estructurados y son legibles. JSON suele ser más compacto; XML usa etiquetas de apertura y cierre y puede validarse formalmente con esquemas.

Códigos HTTP en tres escenarios

201 Created

La tienda recibió un POST y creó correctamente un producto.

400 Bad Request

El formulario envió un precio inválido o dejó un campo obligatorio vacío.

404 Not Found

El cliente solicitó el producto 999, pero no existe.
